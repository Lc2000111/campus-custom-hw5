4 · What would have been simpler as one agent with tools?

My words

As for what would have been simpler as one agent with tools is that the execution process will be more linear and avoid handoff latency.

Evidence
  • #102 is the clearest case (Ticket 102 tab). It needs one lookup (check_rent_due), one request (request_payment) and one draft. Instead it took 4 agent runs and 3 hand-offs, and Accounting was asked to queue the same rent twice (once by Boss, once by Facilities). A single agent would have done those three steps in a straight line, and the 3-minute stall in one sub-agent wouldn't have held up the whole ticket.
  • #101 shows the cost of hand-offs (Ticket 101 tab). It had 6 agent runs, including Customer Service asking Inventory to check the same stock that Inventory was already checking for Boss. That added up to 23 model requests and 46,990 tokens for a 1-shirt order. #102 and #103 each used about 25k tokens.
  • What the team does better: separation of duties. Customer Service and Inventory have no money tools at all, and no agent can approve a payment. On a single agent, that safety would depend on prompts alone. For a shop handling real cash, the hand-off latency buys that safety.
